# 计算机与工程技术 Profile

适用于编程语言、算法与数据结构、操作系统、数据库、网络、人工智能、工程实现。

## 实体

| 实体 | 关键属性 |
|---|---|
| Concept 概念 | 定义、所属层次、易混概念 |
| Component 组件 | 职责、接口、依赖 |
| Architecture 架构 | 分层、模块划分、约束 |
| Algorithm 算法 | 输入输出、步骤、复杂度、适用场景 |
| DataStructure 数据结构 | 组织方式、操作、复杂度 |
| Interface 接口 | 签名、参数、返回值、错误情形 |
| Function 函数 | 功能、参数、副作用 |
| Parameter 参数 | 名称、类型、取值范围、默认值 |
| Protocol 协议 | 消息格式、时序、状态 |
| Workflow 流程 | 步骤、前置条件、失败处理 |
| CodeExample 代码 | 语言、版本、运行环境、输出 |
| Configuration 配置 | 项、取值、影响 |
| Constraint 限制 | 性能上限、兼容性、平台约束 |
| Error 错误 | 现象、成因、排查方式 |

## 关系

`calls` `depends_on` `implements` `inherits_from` `contains` `communicates_with` `transforms` `configures` `optimizes`

- `implements` 方向固定：具体实现 → 抽象接口或协议。
- `inherits_from` 方向固定：子类型 → 父类型。

## 深度

| 深度 | 计算机专属要求 |
|---|---|
| L1 | 技术主题、核心组件名、语言或平台 |
| L2 | 概念定义、接口签名、算法思路、典型用法 |
| L3 | 复杂度分析、依赖关系、配置项影响、常见错误 |
| L4 | 完整实现步骤、多方案对比、版本与环境差异、性能边界 |

## 抽取顺序

概念 → 组件 → 原理 → 算法 → 代码 → 参数 → 使用场景 → 常见错误。

先抽组件边界：接口不先定，后面的调用关系会互相污染。

## 校验要点

- 代码示例必须注明语言与版本；无版本的代码标 `partial`。
- 接口参数与实现一致，不得只写名称不写类型。
- 复杂度结论要能指出前提（最坏、平均、输入规模）。
- 错误条目要能对应到具体的失败现象，不能只写「可能出错」。

# 交互规则

## 一、选择器

功能执行缺参数时，用选择补全，不让用户打字。

1. 选项必须来自已解析的 `structure.json`，不能是空白输入框。
2. 层级逐级收敛：先章节，再内容单元，再知识节点。
3. 每个选项带信息：章节项显示单元数与内容类型分布，节点项显示实体类型与当前深度。
4. 多选时显示已选数量与覆盖范围。
5. 用户不选直接确认 → 执行上次选择或首项，并说明选了哪个。

## 一点五、每个状态都有选项

`guide` 会按当前状态返回 `steps`，每个 step 是一组选项。不要自己编选项，也不要用「请提供更多信息」结束一轮。

| 状态 | guide 返回 |
|---|---|
| 工作区空 | `file`：当前目录里的 .docx/.txt/.md 候选，按修改时间倒序 |
| 多个教材/作品 | `entry`：让用户先选对象 |
| 有教材、无方案 | `scope`（全部 + 各章）+ `depth`（四档，标已有/需抽取） |
| 有方案、未确认 | `confirm`：按方案铺开 / 调深度 / 调范围 |
| 已确认、无实体 | `extract`：先抽哪一章 |
| 有实体 | `scope` + `product`（按 Profile 过滤）+ `depth` |
| 作品、来源 < 3 | `sources`：继续检索 / 用现有来源继续（标注来源不足） |
| 作品、来源够、缺专业拆解 | `analysis`：L2/L3/L4 分析深度 |
| 作品、有拆解、缺听赏指南 | `guide-scope`：按段选 |
| 作品全齐 | `refresh`：打开目录 / 换深度重做 |

产物选项带 `generated` 计数，已经生成过的要标出来，别让用户重复点。

深度选项必须显示「已有 · 直接复用」或「需抽取」。这是用户判断值不值得点的唯一依据。


## 二、深度选择

L1–L4 四档，每档标注状态。

| 选项 | 内容 | 标注 |
|---|---|---|
| L1 结构 | 目录、章节、核心知识点 | 已有 / 需抽取 |
| L2 知识点 | 知识点、概念、定义、原理 | 同上 |
| L3 深度 | 增加证明、推导、适用条件、易错点 | 同上 |
| L4 精细 | 增加完整推导、多解、逐项映射 | 同上 |

- 默认高亮方案里的 `depth_target`，但必须由用户点一次。
- 选低于已有深度 → 直接复用已有实体，只换呈现层。
- 选高于已有深度 → 先增量深化补缺口，再出图。

**这个区分要在实现里写死**：视图深度 ≠ 抽取深度。视图选浅了不该重新抽。

## 三、缓存键

```
key = sha1(slug | scope | product | depth | schema_version | scope_version)[:12]
```

`scope_version` 按范围取：全书取各章版本之和，章节取该章版本，单元取所属章版本。

`version-bump --chapter ch03` 只让 ch03 的视图失效，其余章节继续命中。

## 四、index.html

- 一个产物一条记录，重复生成只更新该条。
- 按章节分组，默认折叠。
- 顶部固定显示覆盖率与未完成范围。
- 由 `render-index` 从 `artifacts.jsonl` 重算，读到的状态是什么就渲染什么，不追加历史。

## 五、回复措辞

必须让用户分得清「新生成」和「复用」：

- 复用：`复用已有产物：第 3 章 · 知识地图 · L2（生成于 11-06 14:22）`
- 新生成：`已生成：第 3 章 · 知识地图 · L3，12 个节点，登记为新产物`
- 替换：`第 3 章 · 知识地图 已按 L3 重建，旧条目已更新`

## 六、禁止

- 未确认方案就抽取。
- 静默使用默认深度。
- 命中缓存却重新生成。
- 用 AI 补充的内容冒充教材原文。
- 把「无对应图类型」的产物硬画成图。
